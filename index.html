1. AI fundamentals

Artificial Intelligence is the field of building systems that perform tasks that normally need human intelligence: understanding language, recognizing images, predicting outcomes and making decisions.

TermMeaning
AIThe broad goal: machines that act intelligently.
Machine learningSystems that learn patterns from data instead of following hand-written rules.
Deep learningMachine learning with multi-layer neural networks.
Generative AIModels that create new text, images, code or audio.
  • Narrow AI: does one task well (spam filter, recommendations). All AI in use today.
  • General AI (AGI): human-level ability across tasks. Still theoretical.

The ML workflow

  1. Define the business problem and success metric.
  2. Collect and clean data.
  3. Prepare features and split into train, validation and test sets.
  4. Train and tune a model.
  5. Evaluate with accuracy, precision, recall, F1 or RMSE.
  6. Deploy, monitor and retrain when data drifts.
Common pitfalls: overfitting (great on training data, poor on new data), biased or low-quality data, and data leakage from test data into training.

Common algorithms: linear and logistic regression, decision trees, random forest, gradient boosting, k-means, k-nearest neighbors, support vector machines.

3. Deep learning

Deep learning uses neural networks with many layers. Each layer learns more abstract features, which is why it excels at images, speech and language.

  • Neural network: layers of neurons with weights, trained by backpropagation and gradient descent.
  • CNN: convolutional networks for images and video.
  • RNN / LSTM: sequence models, largely replaced by transformers.
  • Transformer: the architecture behind modern language models. Its attention mechanism lets the model weigh which parts of the input matter most.

Training deep models normally needs GPUs, which is why cloud platforms are central to AI work.

4. Generative AI and LLMs

A Large Language Model (LLM) is a transformer trained on very large text collections to predict the next token. At scale it can write, summarize, translate, reason over text and generate code.

  • Token: a piece of text the model reads and produces.
  • Context window: how much text the model can consider at once.
  • Temperature: controls randomness. Low for factual work, higher for creative work.
  • Hallucination: confident but wrong output. Verify important answers.
  • Fine-tuning: extra training on your own data to specialize a model.
  • Embeddings: numeric vectors that represent meaning, used for search and similarity.
  • Multimodal: models that accept text, images and audio in one request.

5. Prompt engineering

The quality of the answer follows the quality of the instruction. A strong prompt contains:

  1. Role: who the model should act as.
  2. Task: exactly what to do.
  3. Context: the background data it needs.
  4. Format: table, bullets, JSON, length.
  5. Constraints and examples: what to avoid, plus a sample of good output.
Act as a senior network engineer.
Explain the difference between trunk and access ports
for a junior admin. Use a comparison table and end with
a 3-step Cisco switch configuration example.
Useful techniques
  • Few-shot prompting: show one or two examples of the pattern you want.
  • Step-by-step reasoning: ask the model to work through the problem first.
  • Iteration: refine the prompt from the output instead of starting over.

6. RAG and AI agents

Retrieval-Augmented Generation (RAG)

RAG gives a model your own documents at question time. This reduces hallucination and keeps answers current without retraining.

  1. Split documents into chunks and create embeddings.
  2. Store them in a vector database or search index.
  3. For each question, retrieve the most relevant chunks.
  4. Send the question and chunks to the LLM to write the answer.

AI agents

An agent is an LLM that plans and uses tools (search, databases, APIs, code) to finish multi-step tasks. Give agents the minimum permissions they need and require human approval for sensitive actions.

7. Microsoft Copilot

Copilot is Microsoft's family of AI assistants built on large language models and connected to your work data.

ProductWhat it does
Microsoft 365 CopilotAssists inside Word, Excel, PowerPoint, Outlook and Teams: drafting, summarizing meetings and email, analyzing data, building presentations.
Copilot StudioLow-code tool to build custom copilots and agents connected to your data and business systems.
GitHub CopilotCode completion, explanation and chat inside the developer's editor.
Security CopilotAssists SOC analysts with incident summaries, investigation and threat analysis.

Before deploying Copilot

  • Clean up file and site permissions. Copilot can surface anything the user can already access, so oversharing becomes visible quickly.
  • Apply sensitivity labels and data loss prevention policies to protect confidential content.
  • Define an acceptable-use policy and train users to review AI output before sending or publishing.
  • Pilot with a small group, measure results, then expand.

Starting an enterprise AI project

  1. Pick one clear use case with a measurable result.
  2. Check data quality, ownership and access rules.
  3. Choose build, buy or configure (for example Copilot versus a custom solution).
  4. Run a pilot with real users and a human review step.
  5. Monitor cost, quality and risk, then scale.

10. AI security

  • Prompt injection: malicious text that tries to override the model's instructions. Treat all external content as untrusted.
  • Data leakage: never paste passwords, customer data or confidential code into public AI tools. Use approved enterprise tools.
  • Data poisoning: corrupted training or retrieval data that changes model behavior.
  • API abuse and model theft: use authentication, rate limits and monitoring.
  • Excessive agent permissions: apply least privilege and Zero Trust to every tool an agent can call.
  • Deepfakes and AI-powered phishing: verify sensitive requests through a second channel.

References: OWASP Top 10 for LLM Applications and the NIST AI Risk Management Framework.

11. MLOps and deployment

MLOps applies DevOps practices to machine learning so models ship and stay reliable.

  • Version control for code, data and models.
  • Automated training and deployment pipelines (CI/CD).
  • Containers and Kubernetes for serving models.
  • Monitoring for latency, cost, accuracy and data drift.
  • Rollback plans and A/B testing for new model versions.

12. Responsible AI

  • Fairness: test for bias across groups.
  • Transparency: explain how decisions are made where possible.
  • Privacy: follow data protection rules and collect only what you need.
  • Accountability: a named owner and human oversight for important decisions.

13. Learning roadmap

  1. Foundations: Python basics, statistics, data handling.
  2. Machine learning: scikit-learn and model evaluation.
  3. Deep learning: neural networks with PyTorch or TensorFlow.
  4. Generative AI: LLM APIs, prompt engineering, RAG.
  5. Platforms: Microsoft Copilot, Copilot Studio and Azure AI.
  6. Applied project: build something in your own field, such as an IT helpdesk assistant or an ERP report explainer.
  7. Production: cloud deployment, MLOps and AI security.
