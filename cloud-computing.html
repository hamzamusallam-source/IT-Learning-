Cloud Computing

One mental model first, then each platform on top of it. Learn what the cloud actually is, how its pieces fit together, and how to run it securely and without surprises on the bill.

Path 04Level: Mid8 topics≈ 6 weeks

Topic 1Cloud Fundamentals

Cloud computing means renting computing resources — servers, storage, databases, networks, software — over the internet, paying for what you use instead of buying and running the hardware yourself.

  • On-demand: resources are created in minutes, not ordered and installed over weeks.
  • Elastic: capacity grows and shrinks with demand.
  • Pay-as-you-go: spending moves from capital expense (CapEx) to operating expense (OpEx).
  • Global: providers run regions and availability zones around the world.
Shared responsibility: the provider secures the cloud itself; you secure what you put in it — data, identities, configuration.

Topic 3Hybrid Cloud

Hybrid cloud connects an organisation's own data center with a public cloud so they work as one environment. It suits workloads that must stay on-premises for regulation or latency, while others move out.

  • Private connectivity (VPN or dedicated links) between sites.
  • One identity system across both sides.
  • Consistent management, monitoring and policy.

Topic 4Multi-Cloud

Multi-cloud means using more than one public cloud provider — by design, to pick the best service for each job or reduce dependence on one vendor, or by accident, after mergers and team choices.

Multi-cloud adds flexibility but also complexity: more skills, more consoles, and more places for security gaps. Have a clear reason before adopting it.

Topic 5Cloud Networking

Every cloud gives you a private, software-defined network to place resources in. The concepts are the same everywhere, even when the names differ.

  • Virtual network: your isolated address space, divided into subnets.
  • Security rules: stateful filters on what can talk to what.
  • Load balancers and gateways: how traffic enters and leaves.
  • Peering and private links: connecting networks without the public internet.

Topic 6Cloud Security

Most cloud incidents come from misconfiguration and weak identity, not from the provider being breached.

  • Least-privilege access and multi-factor authentication for every account.
  • Encryption for data at rest and in transit, with managed keys.
  • Logging and posture management to catch risky settings early.
  • No storage buckets or databases exposed to the internet by default.

Topic 7FinOps

FinOps is the practice of making cloud spending visible, owned and optimised — bringing finance, engineering and management into the same conversation.

  • Inform: tag resources and show each team what it spends.
  • Optimise: right-size, switch off idle resources, use commitments and discounts.
  • Operate: budgets, alerts and regular reviews.

Topic 8Cloud DR
