Kubernetes

Kubernetes (often written K8s) runs containers across many servers and keeps them healthy. This guide explains what it is, how it works, and the everyday commands — in plain language, one step at a time.

Part of DevOps & AutomationLevel: Mid10 topics≈ 3 weeks

Topic 1What is Kubernetes?

A container packages one application with everything it needs. That's easy to run on one machine. Running hundreds of containers across many servers — restarting them when they crash, spreading load, rolling out new versions without downtime — is the hard part. That is the job Kubernetes does.

  • Open source: started at Google, now maintained by the Cloud Native Computing Foundation (CNCF).
  • Declarative: you describe the state you want (“3 copies of this app”); Kubernetes keeps making it true.
  • Portable: the same files run on-premises or on any major cloud.
When you may not need it: one or two small applications are often simpler on a single server or a managed app service. Kubernetes pays off when you have many services and teams.

Topic 2Architecture

A Kubernetes cluster has two parts: the control plane that makes decisions, and the worker nodes that run your containers.

Topic 3Pods and Deployments

A Pod is the smallest unit Kubernetes runs: one or more containers that share network and storage. You rarely create pods directly. Instead you create a Deployment, which keeps the right number of pod copies (replicas) running and handles updates.

# deployment.yaml — run 3 copies of a web app
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: web
          image: nginx:1.27
          ports:
            - containerPort: 80
  • Rolling update: change the image and pods are replaced gradually, with no downtime.
  • Rollback: one command returns to the previous version.
  • StatefulSet is used instead for databases and apps that need stable identity.

Topic 4Services and Ingress

Pods come and go and their IP addresses change. A Service gives a group of pods one stable name and address, and spreads traffic across them.

TypeReachable from
ClusterIPInside the cluster only (the default).
NodePortA fixed port on every node.
LoadBalancerThe internet, through a cloud load balancer.

An Ingress sits in front of services and routes web traffic by host name or path (for example /api to one service and / to another), usually with TLS certificates.

Topic 5Configuration and Secrets

Keep settings out of container images so the same image works in test and production.

  • ConfigMap: plain settings such as URLs and feature flags.
  • Secret: passwords, tokens and keys. Only base64-encoded by default — enable encryption at rest and limit who can read them.
  • Namespaces: separate teams or environments (dev, test, prod) inside one cluster.

Topic 6Storage

Containers lose their files when they restart. For data that must survive, Kubernetes uses persistent volumes.

  • PersistentVolume (PV): a piece of real storage — a cloud disk or a SAN/NAS volume.
  • PersistentVolumeClaim (PVC): an app's request for storage (“10 GB, read-write”).
  • StorageClass: lets Kubernetes create volumes automatically when a claim appears.

Topic 7Scaling and Self-Healing

This is where Kubernetes earns its place: it keeps applications running without someone watching all night.

  • Self-healing: crashed containers restart; pods on a failed node move to healthy ones.
  • Health probes: liveness (restart if stuck) and readiness (send traffic only when ready).
  • Horizontal Pod Autoscaler: adds or removes pods based on CPU, memory or custom metrics.
  • Cluster autoscaler: adds or removes nodes in the cloud as demand changes.

Topic 8Kubernetes Security

A cluster has many moving parts, so security needs several layers.

  • RBAC: give users and service accounts only the permissions they need.
  • Network policies: by default every pod can talk to every other pod — restrict it.
  • Image security: scan images, use trusted registries, avoid running as root.
  • Keep it patched: upgrade the cluster version regularly; old versions lose support.
  • Audit logs to see who changed what.

Topic 9kubectl Essentials

kubectl is the command-line tool for talking to a cluster. These commands cover most daily work.

# see what is running
kubectl get nodes
kubectl get pods -n my-namespace
kubectl get deployments,services

# apply your YAML files (create or update)
kubectl apply -f deployment.yaml

# investigate a problem
kubectl describe pod web-7d4b9c8f6-x2k9p
kubectl logs web-7d4b9c8f6-x2k9p
kubectl exec -it web-7d4b9c8f6-x2k9p -- sh

# scale, update, roll back
kubectl scale deployment web --replicas=5
kubectl set image deployment/web web=nginx:1.28
kubectl rollout status deployment/web
kubectl rollout undo deployment/web
Tip: when a pod won't start, run kubectl describe pod first. The Events section at the bottom usually says exactly why — a wrong image name, missing secret, or not enough resources.

Running the control plane yourself is hard work. Every major cloud offers a managed service that runs it for you, so you only manage your applications and worker nodes.
