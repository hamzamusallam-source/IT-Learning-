Database Management Systems

Designing relational databases well, then running a database engine safely: installation, security, backup, tuning and high availability.

Path 07Level: Mid → Advanced8 topics≈ 8 weeks

Topic 1Relational Design

Good design prevents problems that no amount of tuning can fix later.

  • Tables, rows, columns and primary keys.
  • Foreign keys enforce relationships.
  • Normalization removes duplication (1NF, 2NF, 3NF).
  • Denormalize only on purpose, for performance.

Topic 2SQL & PL/SQL

SQL queries and changes data; procedural extensions add logic inside the database.

  • DDL (CREATE, ALTER) and DML (INSERT, UPDATE, DELETE).
  • Transactions: COMMIT, ROLLBACK and ACID properties.
  • Stored procedures, functions and triggers.
  • Bind variables for speed and security.

Topic 3Installation & Configuration

A clean, documented installation saves months of trouble.

  • Check OS and hardware prerequisites.
  • Separate disks for data, logs and backups.
  • Memory and process parameters sized for the workload.
  • Record every setting in a build document.

Topic 4Security & Auditing

Databases hold the most valuable data, so they need layered protection.

  • Least-privilege users and roles.
  • Encryption at rest and in transit.
  • Auditing of privileged and sensitive actions.
  • Remove default accounts and sample schemas.

Topic 5Backup & Recovery

A backup only counts if you can restore it.

  • Full, incremental and archive log backups.
  • Point-in-time recovery.
  • Store copies off-site and offline.
  • Test restores on a schedule.

Topic 6Performance Tuning

Tuning is finding the real bottleneck, then fixing the cause.

  • Read execution plans.
  • Indexes: help reads, cost writes.
  • Find the top resource-consuming queries first.
  • Fix the SQL before adding hardware.

Topic 7High Availability

Keeping the database available when a server or site fails.

  • Clustering for server failure.
  • Standby databases for site failure.
  • Automatic vs manual failover.
  • Regular switchover tests.

Topic 8Replication

Copying data between databases for availability, reporting or distribution.

  • Synchronous: no data loss, more latency.
  • Asynchronous: faster, small risk of loss.
  • Logical vs physical replication.
  • Monitor replication lag closely.
